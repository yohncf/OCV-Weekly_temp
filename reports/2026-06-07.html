Key findings

What the data is telling us

False-success on action surfaces is the highest-trust-impact pattern this week
P0

5 distinct sessions show explicit success confirmations (✅ invite created, Your draft is ready, 41 emails moved, event set to busy with all 4 reminders, invite has been created) for actions that never persisted. All 5 surfaces (Scheduling × 3, Drafting × 1, Triage × 1) are core capabilities; each is P0 per the trust-break rule.

Action-bearing prompts continue to fall through to canned errors

Cancel meetings / create calendar events / compose long emails returned the canned 'I wasn't able to process' string on at least 5 sessions. This is the same Topic 1 / Topic 6 misrouting pattern flagged in prior weeks; the action-vs-informational classifier remains the highest-leverage fix surface.

Rules and folder creation underperform

Three sessions show blank or no-op responses to rule-creation prompts; one shows a confirm-rule loop that never completes. User self-reports 'is rules creation broken?' (Item 55). Worth surfacing to the Rules team as a focused cluster of 4 items.

Search retrieves the wrong document with notable consistency

6 distinct sessions report the model returned a wrong-document hit (PLTR vs SNOW, 'WG: Certificate' vs Death Certificate, wrong meeting-forward notification recipients, wrong approval list). Cross-language (EN, DE, ZH). This is the top Topic 8 (wrong grounding) cluster of the week.

Folder-scope constraints are dropped in summary tasks
P2

Two distinct sessions: user constrains 'EngOps Updates folder' / 'current folder' for a summary; model summarizes the entire inbox. Topic 4 (constraints ignored), P2.

Attachment reading remains a capability gap
P1

3 sessions (File category, Topic 10 input): PDF, PowerPoint, invoice images — Copilot could not extract content from attached documents. Documented-supported file types should be readable; promote to P1.

Capability boundary is poorly signaled

8 sessions in Topic 12 (capability refusal for in-scope). Refusals span 'create calendar events', 'see subfolders', 'see my draft', 'redraft in place', 'see calendar instructions', 'reminders on followed meetings'. Each request is within documented scope; the model is over-refusing.

Calendar correctness (free/busy) on availability replies
P0

2 sessions: slot-finder and drafted availability reply both proposed times the user is already booked for. Topic 11, P0 by the 'Item Count >= 2' rule.

Anecdotal-tier signal

Topic 13 (intrusive UI, n=1), Topic 3 (off-topic output, n=1), Topic 5 (no items): all are anecdotal per the n<3 rule and not worth ticketing this week.
